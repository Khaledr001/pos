## Roles and RLS

| Role | RLS | Owns tables | Used by |
|---|---|---|---|
| `devsfleet_migrator` | bypassed | yes | migrations, seed |
| `devsfleet_app` | **enforced** | no | the API at runtime |

The app role must never own tables: in PostgreSQL an owner is exempt from its
own policies unless `FORCE ROW LEVEL SECURITY` is set, and relying on that flag
is one careless `ALTER TABLE` from a silent cross-tenant leak.

Every request runs inside a transaction that first issues:

```sql
SELECT set_config('app.current_tenant_id', $1, true);  -- true = SET LOCAL
```

Policies compare `tenant_id` against `current_tenant_id()`. With no context set
that function returns `NULL`, `NULL` matches nothing, and the query returns zero
rows — a loud, safe failure rather than a quiet cross-tenant read.

The transaction is mandatory. `SET LOCAL` is transaction-scoped and the pool
hands the same physical connection to unrelated requests; setting the GUC
outside one would leak context between tenants.

Policies are generated by scanning for a `tenant_id` column
(`packages/db/sql/rls.sql`), so a new table is covered automatically.
`pnpm db:migrate` fails if any tenant-scoped table ends up unprotected.

### Verifying

Both must return zero rows:

```sql
-- tenant-scoped tables without RLS
SELECT c.relname FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
JOIN pg_attribute a ON a.attrelid = c.oid AND a.attname = 'tenant_id'
WHERE n.nspname = 'public' AND c.relkind = 'r' AND NOT c.relrowsecurity;

-- RLS enabled but no policy attached
SELECT c.relname FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind = 'r' AND c.relrowsecurity
  AND NOT EXISTS (SELECT 1 FROM pg_policy p WHERE p.polrelid = c.oid);
```

## Conventions

**camelCase in TypeScript, snake_case in Postgres**, via `casing: "snake_case"`.
Set in **both** `drizzle.config.ts` and `src/client.ts` — a mismatch produces
queries referencing columns that do not exist, discovered only at runtime.

**Money and quantities** are `DECIMAL(12,4)`, surfaced as **strings**. Never
`Number()` them; feed them to `Money.toMinor`.

**`updated_at`** is maintained by a trigger, not the application. The POS sync
engine pages through changes ordered by it — a bulk price update run as raw SQL
would otherwise never reach the terminals.

**Soft delete** on anything a document references or the POS syncs. A row that
simply vanishes from a result set is indistinguishable from one that was never
sent, so deletes travel to terminals as tombstones.

## Table map

### Tenancy — `tenants.ts`
`tenants` · `branches`

`tenants.settings` (JSONB) holds VAT config, currency, locales, printing and
sales policy — shape is `TenantSettings` in `@devsfleet/shared-types`. Read it
through `resolveTenantSettings()` so old rows still produce a complete object.

### Auth — `auth.ts`
`roles` · `users` · `refresh_tokens` · `audit_log`

Roles are rows, not code. Nothing branches on a role *name* — authorisation is
always a permission check, so a tenant may add its own roles freely.

`audit_log` is append-only, enforced by trigger.

### Catalog — `catalog.ts`
`categories` · `brands` · `units` · `products` · `product_barcodes` ·
`product_units` · `product_images`

- `products.name_search` — generated `TSVECTOR` (`english`), GIN-indexed with
  `tenant_id` via `btree_gin`.
- `products.search_key` — normalised text (`3/4"` → `3/4in`), `pg_trgm` indexed.
  This is what serves fuzzy and non-English queries; the tsvector cannot.
- `products.attributes` (JSONB) — the schemaless catch-all this catalogue needs
  while it spans electrical, sanitary and paint. Promote a key to a column only
  once it must be filtered or sorted at scale.
- `product_images.checksum` — SHA-256, unique per tenant. The dedup key.
- `product_units` — packaging conversions. Stock is always held in the base
  unit; selling a box deducts `conversion_factor` base units.

### Pricing — `pricing.ts`
`price_lists` · `product_prices` · `price_history` · `customer_prices`

Resolution order, implemented once in the API's price resolver:

1. `customer_prices` — negotiated for this customer + product
2. `product_prices` — on the customer's assigned list
3. `product_prices` — on the tenant's default list
4. error `NO_PRICE_FOR_PRODUCT` — never fall back to zero, never to cost

Every tier is date-bounded, so a promotion expires by itself.
`min_selling_price` is the floor a cashier cannot cross without
`price:override_floor`.

### Partners — `partners.ts`
`customers` · `suppliers`

`customers.whatsapp_phone` is uniquely indexed per tenant — it is the bot's
first query on every inbound message.

### Inventory — `inventory.ts`
`inventory` · `inventory_transactions` · `stock_transfers` ·
`stock_transfer_items` · `stock_counts` · `stock_count_items`

`inventory` is a materialised balance; `inventory_transactions` is the truth.
Both are written in the same transaction. `balance_after` is stored so a stock
card is an indexed range scan rather than a window function over all history.

The ledger rejects UPDATE and DELETE at the database level. Corrections are
compensating `adjustment` rows.

### Sales — `sales.ts`
`quotations` · `quotation_items` · `orders` · `order_items` · `sales` ·
`sale_items`

Three documents, not one status column: a quotation reserves nothing, an order
reserves stock, a sale moves money and deducts stock. A walk-in POS sale jumps
straight to `sales`; a WhatsApp enquiry walks the whole path. Both land in the
same table, so reporting never unions.

Line items snapshot `product_name`, `product_sku`, `tax_percent` and
`cost_price`. `sales.occurred_at` is the terminal's clock (what belongs on the
receipt); `created_at` is when the server first saw it — hours apart on an
offline sale.

### Payments — `payments.ts`
`payments` · `cash_sessions` · `cash_movements`

A payment is a row, not a column on the sale. That is what makes split tender,
later credit settlement, and refunds work without mutating the original sale.

### Purchasing — `purchasing.ts`
`purchase_orders` · `purchase_order_items` · `goods_receipts` ·
`goods_receipt_items`

Stock moves on **receipt**, never on order. `goods_receipt_items.landed_unit_cost`
includes each line's share of freight and duty — using the invoice price alone
understates cost and overstates margin.

### WhatsApp — `whatsapp.ts`
`whatsapp_conversations` · `whatsapp_messages` · `ai_actions`

`wa_message_id` is unique: Meta redelivers on any non-200, and a redelivery must
not insert twice. `conversations.context` (JSONB) carries rolling AI state so
the model is not re-fed the whole thread each turn. `ai_actions` logs every tool
call with tokens and latency — the audit trail for "why did the bot say that",
and the answer to "what is this costing".

### Sync — `sync.ts`
`devices` · `sync_events` · `document_sequences`

`devices.offline_stock_allocation` (JSONB) is this terminal's disjoint slice of
branch stock while offline. `document_sequences` + `next_document_number()`
gives gapless invoice numbering — see D11 in [DECISIONS.md](DECISIONS.md).

## Working with migrations

```bash
pnpm db:generate     # after editing schema/**  — then READ the SQL
pnpm db:migrate      # migrations, then triggers.sql + rls.sql, then verify
pnpm db:seed         # idempotent
pnpm db:studio
pnpm db:reset        # DESTRUCTIVE, dev only, refuses non-localhost
```

`migrate` reapplies `sql/triggers.sql` and `sql/rls.sql` every time. Both are
idempotent, so a table added in this migration picks up its policy and its
`updated_at` trigger without anyone remembering to ask.

Never edit a migration that has been applied anywhere. Write a new one.

## Local connection

```
postgres://devsfleet_app:app_dev_password@localhost:5432/devsfleet         # runtime
postgres://devsfleet_migrator:migrator_dev_password@localhost:5432/devsfleet  # migrations
```

Extensions installed on first boot: `pgcrypto`, `pg_trgm`, `unaccent`,
`btree_gin`. They live in `docker/postgres/init/`, which only runs against an
empty data directory — changing that file requires `pnpm infra:nuke`.
